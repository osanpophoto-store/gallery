# おさんぽフォト ギャラリーシステム 構築記録

## システム概要

パスワード認証付きの写真販売ギャラリー。保護者がイベントごとのパスワードでログインし、写真を閲覧→枚数選択→Stripe決済→自動メール送信（写真添付 or ダウンロードリンク）の流れで完結する。

---

## 構成

| 要素 | 内容 |
|---|---|
| フロントエンド | GitHub Pages（osanpophoto-store.github.io/gallery/） |
| バックエンド | Google Apps Script（個人Gmailアカウントで運用） |
| 画像ストレージ | Google Drive（thumbs / original の2フォルダ構成） |
| 決済 | Stripe（動的PaymentLink生成） |
| メール送信 | GAS GmailApp + Resend APIフォールバック（送信元: order@osanpophoto-store.com） |
| イベント管理 | Googleスプレッドシート |

## Google Drive構成

```
Google Drive/
└── osanpophoto/
    └── イベント名/
        ├── thumbs/      → F列に設定（サムネイル用・個人Gmailと共有必須）
        │   ├── IMG-001.jpg
        │   ├── IMG-002.jpg
        │   └── ...

```

### ファイル名のルール

- **`IMG-001.jpg` 形式（3桁ゼロパディング）で統一すること**
- thumbs・original ともに `IMG-001.jpg` から始まる連番にすること
- Lightroomの書き出し設定: カスタム名 `IMG-` + 連番（開始番号を必ず1に設定）
- 透かしはLightroom書き出し時に処理する（サイトでは透かし処理なし）

⚠️ **複数クラスを別イベントとして登録する場合、originalのファイル名がLightroom通し番号のままだとthumbsの番号と一致しない。必ずLightroomで書き出し開始番号を1に設定するか、ターミナルで一括リネームすること。**

#### ターミナルでの一括リネーム手順

```bash
# originalフォルダに移動（FinderからターミナルにD&Dでパス入力）
cd /path/to/original

# IMG-001.jpg からの連番にリネーム
i=1; for f in $(ls *.jpg | sort -V); do mv "$f" $(printf "IMG-%03d.jpg" $i); i=$((i+1)); done

# 確認
ls *.jpg | head -5
```

### 共有設定

thumbs / original フォルダの両方を個人Gmailアカウント（taiki.kurono@gmail.com）と**編集者**で共有すること。

⚠️ thumbsだけ共有してoriginalを忘れるケースに注意。両方必須。

## Stripe設定

### Webhook

- エンドポイントURL: GASのデプロイURL
- リッスン対象: `checkout.session.completed`
- ※ GASがPOSTのリダイレクトを返すためWebhookは必ず失敗するが、`checkNewPayments` ポーリングで補完するため問題なし
- **StripeからWebhookエラーのメールが届いても無視してOK。エンドポイントは削除してしまっても構わない。**

### 動的PaymentLink

GASがStripe APIで都度PaymentLinkを生成。metadataに以下を埋め込む：

| キー | 内容 |
|---|---|
| `eventId` | イベントID |
| `photoNumbers` | 選択した写真の連番（`001`,`002`... カンマ区切り） |
| `isAll` | 全データかどうか |
| `qty` | 枚数 |
| `customerEmail` | 保護者のメールアドレス |

### 冪等性チェック（二重処理防止）

`checkNewPayments` は処理前にpurchase_logのA列（Stripe決済ID）を確認し、記録済みのIDはスキップする。また `created[gte]` で前回チェック以降の決済のみ取得する。

#### LAST_CHECKのリセット方法（テスト時に使用）

テストを繰り返すと `LAST_CHECK` が現在時刻に近づき過去の決済を拾えなくなる。以下を実行してリセットする：

```javascript
function resetLastCheck() {
  const oneHourAgo = Math.floor(Date.now() / 1000) - 3600;
  PropertiesService.getScriptProperties().setProperty('LAST_CHECK', String(oneHourAgo));
  Logger.log('LAST_CHECK をリセットしました: ' + oneHourAgo);
}
```

1. Lightroomで写真を書き出し（thumbs・original とも `IMG-001.jpg` 形式・開始番号1・透かし処理済み）

前のイベントが終了したら `events` シートの該当行を上書きするだけでOK。purchase_logは引き継がれるので削除不要。Drive共有の自動解除も正常に動き続ける。

## 既知の制限・注意事項

- Google DriveのサムネイルURL（`thumbnail?id=...`）はCORSの制約でCanvas描画不可のため透かし処理はLightroom書き出し時に行う
- メール送信元は `order@osanpophoto-store.com`（個人GmailにSMTP登録済み）
- StripeのWebhookはGASで直接受信できないため1分ポーリングで代替（最大1分の遅延）
- GASの無料枠: 1日の実行時間6分、メール送信100通/日
- イベントIDにスペース・カンマを含めると照合に失敗する（必ずハイフン区切りで命名）

### 給食フォルダを流用して水遊びイベント2件を追加（上書き運用の実例）

給食（たんぽぽ・ひまわり／ゆり・すみれ・あじさい）は販売終了済み（購入受付終了日を経過済み）だったため、上記「上書き運用について」の方針どおり、同じDriveフォルダ・スプレッドシート行を流用して水遊びイベントを追加した。

| 項目 | ねこ・つき・りんご組 | いぬ・ほし・すいか組 |
|---|---|---|
| イベントID | `mizuasobi-neko-tsuki-ringo` | `mizuasobi-inu-hoshi-suika` |
| 撮影日 | 2026/07/03 | 2026/07/10 |
| 写真枚数 | 410枚 | 455枚 |
| 公開開始日 | 2026/8/1 | 2026/8/1 |
| 閲覧終了日・購入受付終了日 | 2026/10/1 | 2026/10/1 |
| 流用元のイベント | 給食(たんぽぽ、ひまわり) | 給食(ゆり、すみれ、あじさい) |
| パスワード | 共通パスワードを使用（2イベントとも同じ） |

フォルダURL（サムネイル・本物データとも）はF列・G列とも変更していない。DriveのフォルダIDはフォルダ名をリネームしても変わらないため、親フォルダ名だけ「水遊び ねこ・つき・りんご」「水遊びいぬ・ほし・すいか」に変更し、中身の給食写真は削除して水遊び写真に差し替えた。

⚠️ **ファイル名の実態と現行ルールの齟齬**: Lightroom書き出し時の自動連番でゼロパディング3桁（`IMG-093.jpg`形式）になっていることを確認した。2026/05/05に決めたv2.0のゼロパディングなしルール（`IMG-93.jpg`）とは異なるが、thumbs・original双方で同じ形式に揃っているため写真の紐付け自体は壊れないはず。次回イベント登録時はLightroom書き出し時のパディング設定に注意し、必ず公開前にテスト購入で写真添付・表示を確認すること。

### カートUIをミニバー＋モーダル方式に変更

写真を1枚選ぶとカートパネルが画面の半分近くを覆い、複数枚選びにくいという問題があったため、以下のように変更した。

- 常時表示は「枚数・目安金額（スマホサイズ基準）・受け取り方法を選ぶボタン」だけの薄いミニバーに縮小（`.cart-mini-row`）
- 受け取り方法（スマホサイズ／A4データ／A3データ／A4プリント／A4パネル）の選択肢は新規モーダル（`#cart-options-overlay`）に移動し、ボタンを押した時だけ表示
- モーダルで方法を選ぶ（`chooseMode()`）と、そのまま購入確認モーダルに直結。従来の「モード選択→購入へ→確認」の3タップから2タップに短縮
- 一度方法を選んだ状態でミニバーのボタンを押すと、モーダルを再度開かず直接購入確認へ戻る
- 料金計算・決済API呼び出し・納品ロジックは変更なし（表示・導線のみの変更）

### 写真表示を横向き（4:3）に変更

水遊びイベントは横向き写真が多いため、ギャラリーの写真枠（`.photo-item`）・購入確認モーダルのサムネイル枠（`.confirm-thumb`）のaspect-ratioを `3/4` → `4/3` に変更。

### GitHubへの反映方法

Claude in Chrome拡張を接続すれば、GitHubリポジトリの「Add file → Upload files」画面からindex.htmlを直接アップロードし、`main`ブランチへのコミットまで代行できることを確認した。手動アップロードの代替手段として利用可能。
